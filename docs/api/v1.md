# ODP API v1

## Purpose

API v1 establishes the technical API boundary for the ODP backend.

This version provides infrastructure for communication between the backend and future client applications.

Business workflows are intentionally excluded at this stage.

---

## Base Path

All API v1 endpoints use:

`/api/v1`

---

## Response Standard

All API responses should follow a consistent JSON structure.

### Success

Example response:

    {
        "status": "success",
        "message": "API is healthy.",
        "data": {
            "service": "api",
            "version": "v1"
        }
    }

### Error

Example response:

    {
        "status": "error",
        "message": "Resource not found.",
        "data": null
    }

---

## Response Fields

### `status`

Indicates the general result of the request.

Allowed values:

- `success`
- `error`

### `message`

A human-readable description of the result.

### `data`

Contains the response payload.

For responses without a payload, `data` should be `null`.

---

## Health Endpoint

### GET `/api/v1/health`

Confirms that the API layer is reachable.

Current implementation:

- Controller: `HealthController`
- Namespace: `App\Http\Controllers\Api\V1`

---

## Scope Control

The following are intentionally excluded from the API foundation:

- Authentication workflow
- User profile business logic
- Order engine
- Fare/price engine
- Payment integration
- Wallet
- Runner task logic
- Vendor system
- Delivery workflow
- Personal Shopper workflow
